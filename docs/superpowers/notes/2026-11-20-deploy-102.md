# Deploy da migration 102 — push de bloqueio e recibos da Expo

Spec: `docs/superpowers/specs/2026-11-20-push-graficos-design.md` (C14, B14).

## Ordem

1. Rodar `supabase/migrations/102_push_bloqueio_e_recibos.sql` no SQL Editor (exige a 101 e a 097; nunca `supabase db push`).
2. Fazer as conferências abaixo.
3. Merge e deploy. A ordem entre deploy e 102 é livre: sem a 102 o cron pula o push de bloqueio e a leitura de recibos em silêncio.

## Conferências (somente leitura)

```sql
select column_name from information_schema.columns
 where table_name = 'notificacoes' and column_name = 'push_enviado_em';              -- 1 linha
select count(*) from public.notificacoes where push_enviado_em is null;            -- 0 logo após rodar
select indexname from pg_indexes where indexname = 'idx_notificacoes_push_pendente'; -- 1 linha
select relrowsecurity from pg_class where relname = 'push_recibos';                 -- true
select count(*) from pg_policies where tablename = 'push_recibos';                  -- 0
select tgname from pg_trigger where tgname = 'trg_notificacoes_so_lida';            -- 1 linha (da 097, intacto)
```

## Depois

- Pedir a uma profissional um bloqueio de agenda: quem aprova deve receber o push (web e app) em até 5 minutos.
- Rodar a 102 de novo é seguro: o backfill só acontece na primeira execução.
- Rollback no cabeçalho da migration.
